# Kanban 模板

此目录包含五个阶段的任务管理，任务文件使用统一的命名格式：

`TASK-XXX-任务名称.md`

其中 XXX 是任务编号（001, 002, ...）

## 任务状态流转

```
Backlog → In Progress → In Testing → In Deployment → Released
```

## 任务文件模板

每个任务文件应包含以下内容：

```markdown
# TASK-XXX: 任务名称

## 基本信息
- **任务编号**: TASK-XXX
- **创建日期**: YYYY-MM-DD
- **创建者**: 用户/AI角色
- **优先级**: 高/中/低
- **状态**: Backlog/In Progress/In Testing/In Deployment/Released

## 任务描述
（详细描述任务的目标和背景）

## 需求来源
（说明此任务从何而来：用户需求、问题反馈、系统优化等）

## 验收标准
- [ ] 标准1
- [ ] 标准2
- [ ] 标准3

## 相关文件
- 文件1路径
- 文件2路径

## 变更历史
| 日期 | 状态变更 | 说明 |
|------|---------|------|
| YYYY-MM-DD | Backlog | 任务创建 |

## 备注
（其他需要说明的信息）
```

## 阶段说明

### Backlog
原始想法和待评估的任务，可能尚不完整或需要进一步澄清。

### In Progress
已开始执行的任务，应有明确的执行计划和负责人。

### In Testing
已完成待验证的任务，需要进行测试或用户确认。

### In Deployment
已验证通过，待发布或部署的任务。

### Released
已完成的任务，将按月份归档到对应子目录。
